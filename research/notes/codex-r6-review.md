**Learn-from-hermes list**

1. FTS5-backed session DB. Hermes makes recall a database problem, not a prompt hack (`research/hermes-agent/hermes_state.py:41`, `:94`, `:791`); adapt that as a principal-labeled Go SQLite store replacing JSONL as source of truth (`pkg/memory/jsonl.go:45`, `:218`).
2. `session_search` as a first-class recall tool. Hermes supports both "recent sessions" and keyword recall (`research/hermes-agent/tools/session_search_tool.py:247`, `:443`); adapt that as `session_search` plus `memory_recall`, with chain/account filters.
3. Separate user facts from environment facts. Hermes's `memory` tool explicitly distinguishes `user` vs `memory` (`research/hermes-agent/tools/memory_tool.py:489`); Ottie should mirror that instead of one global memory blob (`pkg/agent/memory.go:132`).
4. Frozen-snapshot memory semantics. Hermes writes memory mid-session without changing the system prompt (`research/hermes-agent/tools/memory_tool.py:11`, `:23`, `:131`); keep that exact invariant in Ottie.
5. Per-user memory scoping. Hermes threads `user_id` into providers and tests it (`research/hermes-agent/run_agent.py:1179`, `research/hermes-agent/tests/agent/test_memory_user_id.py:67`); adapt it as typed principal scoping, not raw strings.
6. Memory lifecycle hooks. Hermes's provider model covers prefetch, sync, pre-compress, and delegation hooks (`research/hermes-agent/agent/memory_provider.py:16`, `:92`, `research/hermes-agent/agent/memory_manager.py:167`, `:285`, `:320`); adapt with one in-tree provider interface, not plugin soup.
7. Progressive-disclosure skills. Hermes uses `skills_list`/`skill_view` rather than dumping full skill text into the prompt (`research/hermes-agent/tools/skills_tool.py:720`, `:788`); Ottie should copy that immediately.
8. Cached skill index snapshots. Hermes keeps both in-process cache and disk snapshot for skills prompt build (`research/hermes-agent/agent/prompt_builder.py:539`, `:582`, `:650`); adapt that for fast cold start in gateway mode.
9. Unified skill mutation tool. Hermes's `skill_manage` consolidates create/patch/edit/delete and invalidates prompt cache on success (`research/hermes-agent/tools/skill_manager_tool.py:589`, `:640`, `:654`); adapt it with Ottie's consent gate and diff preview.
10. Persist the exact system prompt for resumed sessions. Hermes stores/reuses the prompt to preserve cache identity (`research/hermes-agent/run_agent.py:7512`, `:7533`, `:7555`); Ottie should persist prompt hash plus prompt text snapshot.
11. Session title lineage. Hermes resolves "latest continuation" and autoincrements lineage titles (`research/hermes-agent/hermes_state.py:653`, `:682`); adapt it for human-usable resume/debug flows.
12. Content-based batch resume. Hermes resumes by prompt content, not just numeric index (`research/hermes-agent/batch_runner.py:718`, `:803`); steal that exactly.
13. Strict-provider sanitization. Hermes strips internal fields before hitting strict APIs and recently added schema-type coercion (`research/hermes-agent/run_agent.py:6168`, `:7232`, `research/hermes-agent/RELEASE_v0.8.0.md:76`); adapt it as a validator/repair layer before dispatch.
14. Test what breaks money. Hermes treats prompt caching, resume, user scoping, trajectory infra, and worktree security as load-bearing tests (`research/hermes-agent/tests/agent/test_prompt_caching.py:1`, `tests/cli/test_resume_display.py:1`, `tests/cli/test_worktree_security.py:40`); Ottie should do the same for replay, principal binding, and action ledgers.

**Anti-patterns — things hermes does that Ottie should NOT copy**

- Hidden background self-modification. Hermes spawns review/flush agents that can write shared memory and skills without user-visible consent (`research/hermes-agent/run_agent.py:1964`, `research/hermes-agent/gateway/run.py:785`). For Ottie, that is unacceptable on any path adjacent to money.
- Shared-thread session defaults. Hermes deliberately shares thread sessions across participants by default (`research/hermes-agent/gateway/session.py:444`, `:475`, `research/hermes-agent/RELEASE_v0.8.0.md:91`). A crypto agent should default to per-principal, not socially shared, memory/action context.
- Ephemeral plugin context that is not persisted. Hermes injects plugin context into the current user message specifically to preserve prompt cache, then keeps it out of session persistence (`research/hermes-agent/run_agent.py:7622`, `:7748`). That is bad for forensics.
- Plugin-heavy memory backend sprawl. Hermes supports a built-in memory plus one external provider plugin (`research/hermes-agent/agent/memory_provider.py:3`, `research/hermes-agent/agent/memory_manager.py:73`). Ottie should prefer one in-tree typed memory subsystem if it wants replayable guarantees.
- Dict-schema, stringly tool registry. Hermes's registry is dynamic Python dict schema plus JSON-string dispatch (`research/hermes-agent/tools/registry.py:59`, `:149`). Ottie should not give up Go's chance to make tool arguments typed and effect-labeled.
- Runtime/dependency sprawl. Hermes's packaging story is extras-heavy Python plus Docker+Node+Playwright (`research/hermes-agent/pyproject.toml:13`, `:39`, `research/hermes-agent/Dockerfile:7`). Ottie should keep the single-binary discipline.
